# bug-bot

Running the C. elegans connectome (302 neurons) as a spiking neural network on an FPGA to drive a small robot. Long-term: add reinforcement learning, then scale to the fruit fly connectome (~140k neurons) for a drone.

- Verilog: `lif_neuron` module (3 weighted inputs, parameters for weights) instantiated 4 times in `top_module`, hand-wired. Passes a self-checking testbench against Python golden vectors.
- Verilog, scalable core ✅ (simulation): `core.v` runs the **full 300-neuron worm** and matches the full-network golden files for all 80 steps (and the 4-neuron chain files). One `lif_math` instance, time-multiplexed over all neurons by a state machine: IDLE → CLEAR → POKES → SPIKES → PIPES (`PIPES_SAVE` → `PIPES_A` → `PIPES_B`, once per pipe) → `MUSCLE_LEAK` → UPDATE (`UPDATE_READ` → `UPDATE_SAVE`, once per neuron) → `MUSCLE_UPDATE` → IDLE, started by a one-tick `start_step` pulse, `busy` high while a step runs (~4,600 ticks per worm step, ~46 µs at 100 MHz). Wiring loaded from `.mem` files (`MEM_DIR`), sizes set by parameters `N`, `N_LINKS`, `N_POKES`, `N_POKE_LINKS`, `N_PIPES`. SPIKES skips neurons that didn't fire (one tick each); PIPES visits every pipe (flow always runs), three ticks per pipe (save, side a, side b) so `totals` gets at most one write per tick. Pipe math uses wires (`assign`), 20-bit signed `pipe_flow`, and `$signed({1'b0, pipe_size})` so the 8-bit unsigned size stays positive.

## Model conventions (Python and Verilog must match exactly)
- Integer-only LIF: `v = v - (v >> 3) + total`; spike if `v >= 256`, then reset `v = 0`; otherwise if `v < FLOOR` (−512), set `v = FLOOR`. Voltage stays between −512 and 255 after every step.
- `total` (this step's input, reset to 0 each step) is kept separate from `v` (neuron memory). The leak uses the old `v` before input is added.
- Neuron-to-neuron spikes arrive with a **one-step delay** (from `last_spikes`). Pokes (external inputs) act on the **same step**.
- Sparse format: `connections[sender] = [(receiver, weight), ...]`; `poke_connections[poke] = [(receiver, weight), ...]`.
- Chemical weights are pre-scaled by the parser (`size * K`, signed), so the model just adds them. The one-way circuit pipe links are stored in `connections` the same way, so the model loop doesn't treat them differently.
- Robot readout (muscle buckets): the generated file exports `back_motors` (DA/VA indices) and `forward_motors` (DB/VB indices). Each step, after the neurons update: leak both buckets first (`muscle = muscle - (muscle >> MUSCLE_LEAK)`, `MUSCLE_LEAK = 2`), then add +1 per motor in that group that fired. Decide: both below `STOP_BELOW = 8` → `("stop", 0)`; otherwise the bigger bucket wins, speed = difference between the buckets. Buckets never reach 0 with integer shifts (stuck at 3), so stop uses a cutoff.
- Pipes (gap junctions): `pipes = [(a, b, size), ...]`, each pair once, raw size. Each step, two jobs, both written into `totals` (never `voltages`):
  - Flow: `flow = ((voltages[a] - voltages[b]) * size) >> pipe_shift`, from start-of-step voltages; `totals[a] -= flow`, `totals[b] += flow`.
  - Spike packages: if `last_spikes[a]`, `totals[b] += size * PIPE_K`; if `last_spikes[b]`, `totals[a] += size * PIPE_K` (always +, one-step delay like chemical spikes).
  - Needed because a firing neuron resets to 0, so flow alone can't pass on that it fired. Keep `size * PIPE_K` small: two-way + pipes can ping-pong forever (`PIPE_K` 3 and up runs away).
- 4-neuron test network: indices A=0, B=1, C=2, I=3. Weights: A→B 300, B→C 300, I→B −400; poke 0 → A 300, poke 1 → I 300.
- Golden outputs (6 files): `chain_inputs.txt` (`row[0]*2 + row[1]`), `chain_expected_spikes.txt` (`A*8 + B*4 + C*2 + I`), and `chain_expected_va/vb/vc/vi.txt` (16-bit masked, `%04x`).
- Verilog wiring: `spikes_in` is 3 bits, with `[2]` = WEIGHT_ONE input.
- Full-network golden files (80-step head + tail run, 300 neurons), in `data/`: `full_inputs.txt` (`head*2 + tail` per step), `full_expected_spikes.txt` (one 300-bit hex number per step, **bit i = neuron i**, unlike the chain file where A is the top bit), `full_expected_v.txt` (24,000 lines: one 16-bit `%04x` voltage per line, line = `step * 300 + neuron`). Regenerate with `save_golden` whenever the model changes.

## Known issues
- `neuron_model` is copied in two notebooks (`bug_bot.ipynb`, `touch_test.ipynb`); any math change must go into both. Possible later cleanup: one shared `neuron.py`.
- Verilog: 16-bit `total`/`voltage` with no saturation (a huge `total` would wrap around; Python never wraps). The old `lif_neuron.v` has **no voltage floor**; `lif_math.v` does and replaces it in the new core (doesn't affect the current 4-neuron golden files, whose lowest voltage is −400).
- The old hand-wired `top_module` (one `lif_neuron` per neuron) doesn't scale; the time-multiplexed `core.v` replaces it.
- `core.v` reads its memories instantly (like simulation registers). Real block RAM answers one tick later, and reads inside reads (`totals[link_receiver[slot]]`) take two. For the worm this is fine in Vivado: the wiring tables reach BRAM because their addresses come straight from registers, and `voltages`/`spikes`/`totals` are small enough for LUT RAM, which reads instantly. (Yosys turns `link_receiver` and `poke_receiver` into plain registers instead; check the real tool.) The fly's state won't fit in LUT RAM (fly `totals` alone ≈ 2.2 Mbit vs ~0.6 Mbit of LUT RAM on the Basys 3, ~1.2 Mbit on the Arty), so at the fly stage the jobs need an ask-then-use read tick and one write port ("front desk") for `totals`.
- `PIPE_K` and `pipe_shift` in `core.v` are regs set during the step; they could be `localparam` constants.
- Most real C. elegans neurons use graded potentials, not spikes. LIF is a deliberate simplification. Because a firing neuron resets to 0, pipes can't pass activity well; spike packages and circuit pipe links are workarounds.
- Only one behavior test so far (head + tail touch). Risk of tuning to that one test (overfitting): add more tests before tuning further.
- Pushback margin: forward motors push about +30/step back into AVBL (settles ~240, threshold 256). Rerun the head + tail test after changing `K` or `PIPE_K`.
